## Record format
Each record includes: start line, kind, approx size, export flag, an English summary, and evidence signals (tags/callees/callsite estimate).

## Scope and limitations
- Primary focus is `dev/` (runtime). `tools/` is included only because it generates/guards parts of `dev/`.
- Extraction is **implementation-level**, but intentionally limited to:
  - top-level named `function` / `class` / `const name = (...) => ...` definitions (JS/TS), and
  - 2-space-indented class methods (JS/TS), and
  - `def` / `class` / 4-space-indented methods (Python).
- Not covered: anonymous callbacks, inline arrow functions not assigned at column 0, and nested local helper functions.
- If a record has no nearby doc comment and no manual override, its summary is a conservative, name-derived phrase (identifier split), with evidence signals (`tags`/`calls`) to support quick navigation.
- `used≈N` is a **heuristic**: a sanitized string-match for `name(` within the same file minus the definition; it can under/over-count (comments/strings are stripped, but dynamic calls are not detected).
- “Suspicious unused” uses another heuristic: non-exported + `used≈0` + `repoCalls<=1` (repo-wide string-match on the base identifier). This is a starting point, not proof.

## Synthesis (double-check notes)
- Generated-vs-handwritten ownership is **easy to get wrong** in this repo:
  - Historical note (pre 2026-02-09): `tools/generate_worker_protocol.mjs` also overwrote `dev/physics.worker.mjs` / `dev/viewer_backend.mjs` from `tools/templates/*`.
  - Current (2026-02-09+): the generator only writes `dev/protocol.gen.mjs` / `dev/dispatch.gen.mjs`; worker/backend sources are manual in `dev/`.
- Documentation discoverability is inconsistent:
  - `README.md` and `PLUGIN_GUIDE.md` reference `plugin_dev.md`, but `.gitignore` ignores root `/*.md` by default, which makes the plugin contract easy to drift locally.
- High-risk coupling hotspots (large implementations): `dev/main_renderer.mjs` (SoA render + overlay3d + controllers), `dev/physics.worker.mjs` (snapshot + asset transfer), `dev/viewer_backend.mjs` (worker transport + API), `dev/main_ui.mjs` (state merge + UI bindings).
- Stale/legacy narrative docs exist under `dev/spec/` (they describe native `Simulate::*` flow, not the current JS worker-first runtime). Treat them as historical unless rewritten.
- Concrete mismatch examples (pointers for cleanup planning):
  - Entrypoint still loads `dev/main.nobuild.mjs` via `dev/index.html:870`; the name suggests legacy, but it is the actual bootstrap.
  - `dev/main.nobuild.mjs` ends with a leftover/orphan comment block (~`dev/main.nobuild.mjs:1500`), indicating incomplete extraction cleanup.
  - `tsconfig.json:14` includes only `src/` and `tests/`, while tracked TS lives under `dev/` (e.g. `dev/viewer_state_types.ts`), so editor/type tooling may silently miss it.
  - `dev/favicon.ico` is 0 bytes (likely placeholder); decide to replace with a real icon or remove.
